System architecture · the index engine and its two adapters

B2 — how the system is built

B2 is a local-first Markdown vault with an AI layer that surfaces semantically similar, not-yet-linked notes for you to connect. This repo is the index engine + its two adapters (the b2 CLI and a Tauri desktop app): a SQLite store treated as a disposable projection of your Markdown — nothing durable outside your notes — real local AI behind two enumerated seams, and the typed Vault API both adapters drive. This page traces the whole architecture through one real vault — the golden fixture the test suite runs on — so every claim is concrete and checkable. The why behind each choice is an ADR; the normative spec is design/.

model-free · deterministic suite 5 crates: b2-core · b2-embed · b2-llm · b2-cli · b2-desktop Rust 1.96 · edition 2021 · one static binary kernel: init · reindex · status · search · similar · link · neighbors · explain · add · write · mv · rm · ask · chat

The suite is integration-first: most tests open a real SQLite database, ingest a real vault on disk, and assert on the resulting projection — so it describes the built system, not mocks of it. Nothing is #[ignore]d; the checks that need a real model live in the out-of-CI eval harness, which runs on demand and therefore actually runs.

The governing equation

One equation shapes every decision (ADR-0002; invariants S1–S5). Keep only this:

index = projection of ( the vault directory )
Markdown vault → ingest → b2.sqlite (disposable) → search · neighbors · explain · similar · ask

Delete b2.sqlite, rebuild it from the Markdown — it must come back identical. Exactly one thing is durable and un-derivable: your vault (the source of truth for both knowledge and every committed connection). There is no state anywhere outside your notes. Everything downstream is this equation defended.

Tier 1 · the vault — source of truth

Notes + every committed edge, plain .md, fully usable in Obsidian with no B2 — plus resource peers (PDFs, images, clippings) and the folder tree itself. Stays pristine: B2's only writes are surgical and in frontmatter; the body is 100% the human's.

Tier 2 · b2.sqlite — disposable cache

FTS5 + plain vector tables scored in-process + the typed graph. Disposable: holds nothing that can't be reconstructed from the vault. Drop it, reindex, get an identical index.

A whole vault is one portable folder: the index lives under <root>/.b2/, a dotfolder Obsidian and the vault scanner both ignore. Point B2 at a folder of Markdown — that is the entire setup.

Five crates, cleanly layered

The engine owes nothing to the two adapters above it or the two model crates beside it. The AI-heavy crates sit behind traits defined in b2-core — the Embedder and LlmProvider seams — so the engine and its whole fast suite never import a tensor or an HTTP client, and adding the desktop UI added one adapter, not new architecture (ADR-0012).

b2-core · the engine

Turns a folder of Markdown into a queryable index and keeps it a pure function of disk. Model-free (no candle, no network) so its suite is fast and deterministic. rusqlite (bundled SQLite + FTS5), blake3, yaml — no vector extension: vectors are plain tables scored in-process (ADR-0006).

  • note · ingest · chunk · link · relation
  • db · graph · search · discover · chat
  • embed · llm — the two seams + their fakes
  • add · mv · vault (the façade)
b2-embed · the real embedder

LocalEmbedder: candle-backed BERT (bge-base 768-dim default, bge-small 384-dim supported), pure-Rust inference. b2 init downloads + verifies into a shared XDG cache. All heavy ML deps live only here (ADR-0020).

b2-llm · the real chat provider

A hand-rolled sync OpenAI-compatible SSE client over ureq behind the LlmProvider seam — one wire shape (POST /chat/completions, streamed), Ollama by default, any compatible endpoint by config. Owns the stream's quirks as tests: keep-alives, CRLF, mid-stream errors, a stream that stops without [DONE] (a truncated answer, honestly marked — not an error). No async runtime anywhere (ADR-0011).

b2-cli · the adapter

The b2 binary. Holds no engine logic: parse args, pick + inject the embedder and chat provider, call the Vault façade, print (human, streamed, or --json for agents). Funnels every error through user_message so nothing internal leaks.

b2-desktop · the GUI adapter

The Tauri host — the GUI sibling of b2-cli, equally logic-free: each #[tauri::command] is deserialize → one Vault call → serialize, reusing the CLI's --json view types as the IPC contract. The ui/ frontend (Vite + vanilla TS + CodeMirror 6) renders the read → discover → link → edit → chat loop; two adapters over one façade can't drift.

Ground truth: the layering is enforced by where deps live. b2-core's Cargo.toml has no candle and no HTTP client; the whole engine suite runs on the deterministic fakes. The real models are reached only through b2 init, a configured chat endpoint, and the out-of-CI eval harness.

The prose [[…]] is a bare, untyped references edge (origin=inline) — the body carries no B2 syntax, so a verb or an explanation can never be parsed out of prose. The frontmatter b2_relations: entry is the typed edge (origin=frontmatter), the only place a verb and a "why" live. Both are human-authored here — B2 reads them; it writes such a line only when b2 link asks it to. Note the same target under two verbs: dedup is frontmatter-wins on same-(target, type), so these two coexist. One ingest yields a known-good graph the tests match whole.

FLOW ①  Ingest — vault becomes index

crates/b2-core/src/ingest.rs

b2 reindex is the write path that realizes the governing equation. It composes two separately-invokable passes: model-free project_vault (notes, resources, chunks, FTS, edges) and embed_vault (fill the DB-derived set of chunks still missing a vector). Projection's one subtlety: a note can link to one the walker hasn't reached yet, so link resolution must not depend on file order — it runs in two phases.

walk the vault (dotfolders skipped, sorted) → Phase 1 · notes + chunks (+FTS) → fills the path set → Phase 2 · edges → embed pass · fill missing vectors
  • Phase 1 projects each note's frontmatter and chunks its body (the structure-aware qmd chunker: ~450-token target, overlapping, cut at Markdown breaks, each chunk stamped with its heading_path breadcrumb); chunk text lands in chunks_fts immediately, so keyword search works before anything is embedded. This fills notes(path) — the set of paths a link may resolve to — for the whole vault.
  • Phase 2 derives edges by parsing each body's links + frontmatter b2_relations: and resolving every [[path]] against the now-complete resolver. From spaced-repetition.md that's two directed edges to memory.md: a bare body references and a typed frontmatter supports.
  • Ingest writes nothing to the vault. A note's identity is its vault-relative path (ADR-0003), so there is no id to mint and no line to add — the file B2 read is the file B2 leaves, and a reindex of a git-versioned vault shows no diff.
  • The embed pass batches every chunk still missing a vector through the seam into embeddings — metered (per-batch progress) and cooperatively cancellable, which is what lets the desktop run it in the background. A projected-but-unembedded vault is already browsable: keyword search works, and search degrades to BM25-only rather than failing.

Incremental by default, ≡ a full rebuild. A note whose body_hash is unchanged and whose chunks all still have vectors reuses them verbatim — only edited notes re-embed, and since vectors are addressed by the hash of the text that produced them, only genuinely new text costs a model call. Both paths replace rather than accumulate: re-projecting a note deletes its old chunks (FTS triggers fire) and all its edges, then re-derives every edge from the current Markdown. Because every edge is Markdown-derived, a one-note re-parse is exactly a one-note slice of a full rebuild. The whole-vault pass owns every reconciliation — pruning rows for files the walk no longer met, collecting vectors no chunk references — and single-note paths never prune. b2 reindex --dry-run previews the same decision, writing nothing.

Ground truth: graph.rs · one_note_reindex_equals_full — incremental re-index of one note yields a byte-identical edge set to a full rebuild, and a second reindex is identical again (idempotent). chunks.rs proves replace-not-accumulate; ingest_resolver.rs confirms a link resolves from either authored form; project_embed.rs pins the projection/embedding split; dry_run.rs proves the preview writes nothing. ↳ the indexing deep dive covers incremental skip, --force, batching.

The schema — a derived projection

crates/b2-core/src/db.rs

Every table is a projection of the vault; nothing here is a source of truth. The schema is derived from the data model (design/data-model.md) — it must satisfy the model, never the reverse. A schema change is a version bump + rebuild, never a data migration (S5).

TableHoldsDerived from
notespath (PK), type, title, created/updated, body_hash — identity is the path; children reference it ON UPDATE CASCADE, so a move is a re-keyMarkdown
note_aliasesfrontmatter aliases:, per noteMarkdown

note_centroidsone centroid per note, maintained by the embed pass — discovery's O(notes) stage-1 shortlistderived
edgestyped graph: src_path → dst_path (nullable → dangling) or dst_resource_path, type, origin ∈ {inline, frontmatter}, explanation, occurrence — a deterministic id from (src, dst, type, occurrence); every edge authored + activeMarkdown
metaschema_version, embed_model_id, embed_dimbookkeeping

Two schema details do load-bearing work. There is no status column and no lifecycle — an edge exists iff it is written in the Markdown, so origin only records which home it came from (an inline body link, or a frontmatter b2_relations: entry). And the vector tables (embeddings + note_centroids) are created outside the base migration, at embed time: their existence is the "this vault has an embedding space" signal the projected-but-unembedded fallbacks key on, and meta.embed_model_id/embed_dim record the space's identity — the compute device folds in, so a Metal build is a different space (ADR-0007).

The substrate bet. One embedded store answers every query at once — FTS5, vectors, and the typed graph — so b2 similar can join all three in one transaction. No vector extension is involved at all (ADR-0006): vectors are plain BLOB tables read with one sequential statement and scored in-process, so the whole thing is one statically-linked binary with stock SQLite. Concurrency rides on SQLite's own locks — any number of readers, one serialized builder, and a reader is never refused (ADR-0021, invariant C1). substrate.rs proves a BM25 query and a vector scan run against the same connection.

FLOW ②  Search — hybrid retrieval with an evidence verdict

crates/b2-core/src/search.rs

BM25 keyword search and brute-force vector KNN run over the same index and fuse with Reciprocal Rank Fusion (Σ 1/(k + rank + 1), k=60), resolved from chunks up to notes (ADR-0008). On a projected-but-unembedded vault the vector half is skipped and results are BM25-only — degraded honestly, never an error.

# keyword + semantic, fused — one command
$ b2 search "how does forgetting affect recall"
0.0328  spaced-repetition (notes/spaced-repetition.md)
    Spaced repetition exploits the [[concepts/memory|Human memory]] retrieval curve.
0.0161  memory (concepts/memory.md)
    The brain encodes, stores, and retrieves information…

A note's display name is its filename (invariant L2) — the fixture's frontmatter title: is inert, read back and preserved, never a second source of truth for the name.

  • Raw natural language is sanitized into a safe FTS5 expression — each alphanumeric term double-quoted so nothing is read as an operator, OR-joined for recall (punctuation is FTS5 syntax and would otherwise crash the parse). The index it matches is stemmed (porter unicode61) — a measured verdict from the eval harness, not a default.
  • A served result is a claim of evidence (invariant D2, ADR-0015): hybrid_search carries the absolute signals RRF discards, and a query the vault holds no lexical or semantic evidence for answers "no matches" — none of its nearest guesses are shown. --json is therefore an object: the rows plus the vouched verdict, so an agent can be honest about rows a human is never handed.
  • A fused-score tie breaks on the dense signal's rank — a policy decided by the eval, never left to projection walk order.
  • A graph-filtered variant — "nearest chunks whose note is within k typed hops of note X" — is the embeddings ⨝ chunks ⨝ edges join. It searches within an already-related neighborhood (near ∩ connected). Discovery is its complement (near ∖ connected).
Ground truth: search.rs locks k=60, the tie policy, and the join; cli.rs drives the three verdict states through the built binary. Honest scope: under the fake embedder the vector half isn't semantic, so these prove the plumbing, not model quality — that's the out-of-CI eval harness (make eval; crates/b2-embed/evals/README.md is the overview and the notebook of record). ↳ the retrieval deep dive walks every stage, pool width, and constant.

FLOW ③  Similar → link — surface, then commit, connections

crates/b2-core/src/discover.rs · note.rs (add_relation)

b2 similar <note> surfaces the notes most semantically similar to an anchor that you haven't linked yet — instantly, locally, free: a two-stage scan over the vectors already in the index, with no model call and no network (ADR-0009). The machine finds the candidates; you supply the judgment and the type. This is the reason B2 exists.

The one idea — a candidate is near ∖ connected
anchor's stored chunk vectors→ centroid shortlist — O(notes)− reachable_within(anchor, 1)→ exact max-sim per shortlisted note→ rank → cap(limit) — the ranked list, always
  • No re-embedding, no model call. The anchor is its already-stored vectors — discovery is passage↔passage, and the run reads only what reindex already wrote.
  • Max-sim to the note. Every other note scores by its single best chunk-pair similarity, carrying the winning chunk as the evidence passage B2 shows you.
  • Subtract the graph — its only role here. The anchor + direct neighbours are excluded up front; a 2-hop note (triadic closure) survives, ranked purely by semantic score.
  • The ranked list is always served — limit is a cap, not a promise (invariant D1). No anchor-local statistic gates the list, because such a test cannot distinguish nothing is related from everything is related; the per-candidate z survives ungated as the strength band's input, and an empty result means only that nothing unlinked has stored vectors to compare. The measurements behind the rule are ADR-0014's record.

In our fixture the two notes are directly linked, so each is excluded as the other's candidate — a correctly empty result, which is exactly the assertion discover.rs pins.

You saw a candidate worth connecting; now you commit it. There are exactly two ways a connection becomes real, both authored in Markdown — B2 never proposes an edge on its own, and there is no inert queue to accept from (ADR-0010):

a candidate from b2 similar→ your judgment → b2 link (frontmatter) or a [[link]] you write in the body → reindex → active edge
  • b2 link <src> <dst> [--type <verb>] [--explanation …] appends one typed-link string to the source note's frontmatter b2_relations: — never the body — then re-projects the note, so the edge materializes as origin=frontmatter straight from the line just written. Committing is a projection of an authored line, which is what keeps every edge traceable to a real line in the Markdown. --type takes the closed stance core — references · supports · contradicts — and refuses anything else (a hand-written tail verb is still tolerated, verbatim).
  • Or write a body link yourself — always untyped references: the body has no B2 syntax, so no verb and no "why" is ever parsed out of prose. B2 reads it on the next reindex; it never writes the body. The desktop's other authoring gesture is the same thing: dragging a Similar card onto a line types a [[wikilink]] into the editor's buffer.
what b2 link writes into the source note
---
type: concept
title: "Spaced repetition"
b2_relations:
  - "supports [[concepts/memory.md]]"  # ← appended
---

Frontmatter only. The body is byte-unchanged. On the next reindex this line re-derives as an active origin=frontmatter edge — no separate record anywhere.

Ground truth: discover.rs and discover_surfacing.rs pin the complement and always-serve; note.rs · add_relation + frontmatter.rs pin the one-line frontmatter append with the body byte-unchanged; graph.rs pins that a committed edge re-derives identically to a hand-authored one. ↳ the retrieval deep dive walks the two-stage scan with its constants.

FLOW ④  Grounded chat — ask your vault, get cited answers

crates/b2-core/src/chat.rs · Vault::ask · crates/b2-llm/

b2 ask "…", b2 chat, and the desktop's chat pane (⌘J) stream an answer grounded in your own notes: the model answers only from passages retrieved out of the vault and cites them by [n]. Chat is a reader of the index and adds nothing to it.

condense (multi-turn only)→ retrieve — search_chunks, top 10→ assemble the grounded prompt→ stream tokens (cancellable)→ cite — [n] → (path, excerpt)
  • Condense degrades, never breaks. A follow-up question is rewritten into a standalone query by a provider call; on failure it degrades to the raw question, so that step can never break chat.
  • Retrieval is flow ② unchanged (search_chunks at ASK_PASSAGES = 10, BM25-only fallback included). Prompt assembly is core logic, not an adapter's.
  • Every surface streams. Tokens flow up through the caller's callback, whose return value is cooperative cancellation at token granularity — sync, no async runtime (ADR-0011). Both adapters cancel the same way (Ctrl-C / Esc) and render what already arrived: a cut stream is a truncated answer, honestly marked, never an error. --json is a JSONL event stream for the same reason.
  • Citations resolve, text is never rewritten. [n] markers resolve to (path, excerpt) in the returned AnswerView; a hallucinated marker resolves to nothing.
  • Nothing model-derived is stored. No table, no cached response, no meta row, session-only history — so swapping chat models is a config change, never a reindex. The default endpoint is local (Ollama); a cloud endpoint exists only by explicit configuration, and the desktop keeps its API key in the macOS Keychain, never in a config file (invariant M5). Model output is untrusted content, sanitized at the render surface like any note (ADR-0016).
Ground truth: ask.rs pins condense, retrieve, cite, and cancel against the deterministic FakeLlm; b2-llm's own suite pins the wire quirks — keep-alives, CRLF, mid-stream errors, the missing [DONE]. Chat needs a model server: ollama serve + ollama pull llama3.2, or any OpenAI-compatible endpoint via --llm-url/B2_LLM_URL; B2_LLM=fake is the deterministic provider.

The write discipline — losslessness & surgical edits

crates/b2-core/src/note.rs · add.rs · mv.rs

The vault stays the human's. A parsed note keeps its raw text verbatim and records only the byte spans of the frontmatter block; serialization returns those raw bytes. So parse → serialize → parse is byte-identical — unknown keys, comments, odd whitespace, a missing final newline all survive. Against that backdrop, every byte B2 writes is the mechanics of a command you invoked — B2 makes no unbidden writes at all (ADR-0004):

Frontmatter, surgical
  • add_relation — one YAML-quoted typed-link appended to b2_relations: (the b2 link path).
  • write_frontmatter — a splice of the human's own frontmatter bytes from the desktop drawer; the body is untouched.
Whole-file ops (CRUD)
  • b2 add — create a note (minimal frontmatter; nothing is added on first sight).
  • b2 mv / rm — move or delete notes, resources, folders; a move rewrites inbound [[oldpath]] link text.
  • write — the body splice (stdin or the editor), guarded by a content-hash revision. Never authored by B2.
  • import — handed bytes copied verbatim, then projected (the desktop's drag-in).
b2 mv never breaks the graph. A note's identity is its path, so a move is a re-key, not a rebuild: children reference notes(path) ON UPDATE CASCADE, and the same statement that renames the row carries chunks, vectors and edges across with it — backlinks show the same set before and after, and not one chunk is re-embedded. Inbound link text is repaired too, and only in the exact files the materialized graph names — bounded, never an O(vault) scan; a prefix-sharing [[foo-bar]] is never touched when moving foo. Move a note outside B2 and the bargain is the honest one: the links dangle, visibly, until you repair them — and content-addressed vectors make the delete-plus-create re-embed nothing.
Ground truth: roundtrip.rs pins losslessness; frontmatter.rs the surgical writes; mv.rs pins graph-unchanged, byte-exact inbound diffs, prefix-safety, vector reuse, and honest dangling on out-of-band moves; add.rs / rm_delete.rs / import.rs / dirs.rs pin the rest of the CRUD surface.

The AI seams — fakes for CI, real models for users

Every AI part sits behind a swappable trait defined in b2-core (ADR-0005; invariant M1). The engine is built and tested against deterministic fakes; a real model drops in through the identical seam with no schema or flow change — which is why the whole suite runs with no live model, no wall clock, and no randomness. There are exactly two, and they differ on the one axis that matters: what they are allowed to store.

Embedder — embed::Embedder · carries the index's identity

Fake: FakeEmbedder blake3-hashes text into a vector — identical text → identical vector, deterministically. KNN is reproducible; not semantic. Real: b2-embed::LocalEmbedder, candle BERT, CLS-pool + L2-normalize (so the in-process L2 ranks by cosine), asymmetric query prefix, dim read from the model's own config.json.

The swap is safe by construction (invariant M2): meta records (embed_model_id, embed_dim), device tag included; on a change the vector tables are dropped and a full re-embed follows on reindex. Opening a vault never mutates the vector space; a stale search fails fast with ModelMismatch rather than mixing spaces.

LlmProvider — llm::LlmProvider · deliberately carries none

The chat seam behind flow ④. Fake: FakeLlm echoes citation markers for its passages, so the whole flow is testable with no model. Real: b2-llm's sync SSE client. Streaming and token-granular cancellation are in the trait from day one, because that is the kind of contract that calcifies.

The contrast with the embedder is the point. Chat stores nothing, so swapping chat models never touches the index — chat config is adapter-level (flags/env on the CLI, Settings on the desktop, resolved once in b2_llm::LlmConfig), never vault or index state. Model-compensating machinery is deferred by default — if another model seam lands it's a reranker (post-fusion, changes ordering, not the store), an enumerated seam like these two.

the relation vocabulary — closed core + tolerated tail · relation.rs · ADR-0010
  • references → referenced-by  (neutral)
  • supports → supported-by  (for)
  • contradicts ↔ (symmetric)  (against)

A closed three-verb stance core is your typing palette on b2 link --type and what all queries rely on; each ships a display-only inverse label and a symmetry flag (edges are directed and stored once; inbound neighbors render the inverse). Three, not thirty, because stance is the one thing embedding similarity cannot infer — the vectors already tell you two notes are about the same thing; whether one backs or fights the other is what only a human knows. A tail verb a human writes by hand (e.g. inspired-by) is kept verbatim, treated as opaque and directed. The core is a relaxable policy, not a structural assumption: adding a verb is one entry in relation::CORE.

It owns the connection and the injected seams, and returns display-ready view structs the CLI prints and the desktop reuses as its IPC contract. Grounded in the tests

Nothing here is aspirational: the suite is the executable specification, integration-first, and every property above is asserted in it. Most tests share the golden vault, copied into a temp dir before every run — the copy plus CI's tree-clean assertion is what stands behind "no unbidden writes".

  • The engine suite (cargo test -p b2-core, the bulk of the weight) — one integration file per property, named for it: substrate · roundtrip · ingest_resolver · chunks · fts_tokenizer · graph · embed · project_embed · cancel · search · discover · discover_surfacing · frontmatter · explain · dry_run · add · mv · rm_delete · dirs · import · read · write · write_frontmatter · list · resources · hidden · ask · logging · vault · props — plus the in-crate units (parse, relation vocabulary, chunker, …).
  • The CLI end to end (cli.rs) — every command through the spawned real binary, human and --json, exit codes included.
  • The adapters stay dumb — b2-desktop's suite pins commands, errors, fs-watch, and the menu; b2-embed pins config, the model registry, and provisioning; b2-llm pins the SSE wire shape. The ui/ pure-logic suite runs under node's own test runner.

The two gates are make check (fast, the working loop) and make ci — verbatim what CI runs (ADR-0018). Nothing is #[ignore]d: a check that genuinely needs the real model lives in the eval harness (crates/b2-embed/evals/), which runs on demand and actually runs. Model quality never flakes CI (ADR-0013). Open any file named above; it is the ground truth this page paraphrases.

Not yet built

An honest architecture names its boundaries. What remains is tuning, scale, and packaging — tracked in GitHub Issues, not gaps that slipped through.

  • Semantic quality in CI — never. The engine suite proves plumbing on the fake embedder; the real model is measured by the out-of-CI eval harness (make eval and friends), a model-free rank-stability probe (make stability), and a real-vault calibration command (make calibrate). Every shipped ranking verdict traces to a recorded run on the issue that drove it; crates/b2-embed/evals/README.md is the notebook of record.
  • A cross-encoder reranker is the likely next seam — post-fusion, it changes ordering, not the store — gated on the eval like everything else. Query expansion sits behind it in priority.
  • Resource content search — resources are inventoried and are graph targets today; chunking and embedding them is designed, not shipped (design/data-model.md §10).
  • Packaging/distribution — B2 ships as source today; the real build is still ahead.
